## 2. 范围与强制边界

1. Core 权威性仅针对 Hub 受管状态；外部事实必须有证据，证据不足为未知。
2. Hub 调度的能力要经 Core 权限校验；不能承诺限制其他同用户 Windows 进程的全部操作。
3. `LOCAL_READ`、`EXTERNAL_DISCLOSURE`、`LOCAL_EXECUTE` 独立授权，默认拒绝，并在执行/交付时重新检查。
4. Session Ownership、Epoch/Lease/Generation、GUI 焦点和共享资源锁须联合考虑。
5. 人工接管后阻止新自动写入；即使对账通过也必须用户明确确认后才能恢复。
6. 提交、执行、保存、交付和验收的事实不得互相替代；结果未知时不得盲目重试。
7. Workflow Run 固定 Revision / 能力契约；旧的撤销授权不能因固定版本而继续有效。
8. 本地开发者模块需要用户明确建立信任；独立 Worker / Manifest 不等于 Windows 安全沙箱。

上述为便于审查的摘要，不替代批准全文。
