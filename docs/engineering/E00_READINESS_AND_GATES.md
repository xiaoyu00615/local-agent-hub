## 3. 与后续真实应用的边界

- **E00 全部 PASS** 只允许进入 F2 最小协议冻结审批，不代表网页桥接、工作区边界、GUI、DSH 或终端实机验证完成。
- E01 验证文件边界；E02 验证一个真实网页会话的工具请求与回传；E03 验证 WorkBuddy GUI；E04 验证 DSH ACP；E05 验证受控 Terminal/Test；E06 验证实际工作流恢复；E07 验证 Web Console 用户流程。
- 任何阶段发现与 F1 已批准不变量冲突，应停止相应变更并通过正式 ADR 申请裁决。

## 4. 必须阻断的失败事件

- 未经授权调用受控能力。
- 错误会话或错误端点接受写入。
- 人工接管后未确认恢复自动写入。
- 外部操作结果未知却自动重复有副作用的业务尝试。
- 将 ACK、提交、交付、业务验收错误地当作同一个事实。
- 将同用户 Worker 声明为操作系统强隔离环境。

## 5. 证据及状态标记

每个正式 caseId 使用 `NOT_RUN`、`PASS`、`FAIL`、`BLOCKED` 四态。只有实际运行、有环境指纹及可复核证据才能标记 PASS。测试设计阶段不得预填 PASS；失败必须创建缺陷记录与复测跟踪。
