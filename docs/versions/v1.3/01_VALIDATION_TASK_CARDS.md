# 01｜E00–E07 最小验证任务书

**所有用例当前状态：NOT RUN。** 验证操作只能发生在未来的已授权测试环境。优先使用合成数据、专用测试会话、临时目录和无副作用动作；绝不在真实重要文档上做破坏性测试。

## 公共证据要求
每次试验保留 caseId、环境指纹、协议/Adapter/应用版本、Run/Task/Attempt、目标绑定 ID、请求意图、权限判定、时间线、状态证据、输出摘要、预期与实际结果、结论、可复现说明。涉及内容外传的记录留脱敏摘要和受控引用，不把原文秘密放进普通日志。

## E00｜模拟 Adapter 与协议边界（G0/G1）
**目的**：在不依赖真实 AI 应用的前提下验证 LMP、模块 SDK、权限、任务状态和恢复基本语义。
**环境**：独立新项目/测试数据库；一个模拟 Agent、一个模拟只读工具、一个故意断线的模拟 Adapter。
**正常用例**：注册 Manifest→握手/版本协商→声明能力→发起 Turn→接受确认→提交证据→结果持久化→结果交付→验收；模块禁用/重新启动后可恢复读取持久化状态。
**异常用例**：不兼容协议、无效 Schema、过期 Grant、重复 messageId、重复 idempotencyKey、旧 ownershipEpoch、ACK 延迟、先到结果后到进度、Core 崩溃窗口、Adapter 崩溃。
**必须通过**：不兼容拒绝；不同 ACK 不串义；权威事实重启后可复原；重复外部副作用不得自动发生；旧 Epoch 无效；删除测试 Adapter 后 Core 无需重新编译且保持正常。
**降级**：E00 失败不得进入自动化真实副作用试验。

## E01｜授权工作区只读查询（G2-Reader）
**目的**：证明文件读取既可用又不会越界，也不会暗自传给网页 AI。
**数据**：独立合成工作区（例如普通源码、Markdown、空文件、长文件、不同编码、同名文件）；工作区外放置无害测试文档；包含模拟敏感文件名/假数据但不使用真凭据。
**正常用例**：列目录、按文件名查找、内容搜索、按行读取、查询 stat/hash；验证范围、版本、截断、编码；项目无 `rg` 时仍可完成基础搜索。
**异常用例**：`..` 路径穿越、Windows Junction/符号链接跳出根目录、路径大小写与大小规范化问题、文件中途改变、超大文件、敏感排除规则、撤销授权、目录扫描限额、结果外传未经批准。
**必须通过**：零越界读取、零未经授权外传；路径最终对象和请求范围一致；失败原因可审计；敏感排除规则有效；每次读取的结果来源可追踪。
**降级**：不能安全验证链接边界时，首版可保守拒绝遇到重解析点的路径，不能放宽检查。

## E02｜网页 AI ↔ 本机只读工具（G2-Web）
**目的**：验证一个经授权的网页会话能够提出候选请求、获取经 Core 允许的结果，且返回正确原会话。
**前置条件**：目标网页、测试账号/会话、合法的连接方式、浏览器 Profile 与来源、会话定位判据、已完成 E01，明确 Local Read 与 External Disclosure Grant。
**正常用例**：指定非敏感文件片段 → 候选请求与对应轮次绑定 → Core 记录/审查 → Reader 读取 → 对外传输再次鉴权 → 浏览器连接器投递到原会话 → 验证对端接收状态。
**异常用例**：页面刷新、Service Worker 重启、切换对话、关闭标签页、插入人工消息、同一候选文本重复出现、文件中嵌入冒充工具请求的文本、失效会话标识、撤销授权、结果交付中断。
**建议批次**：30 次正常链路 + 专项异常注入；安全事件 0 容忍。批次不是绝对可靠性证明。
**必须通过**：零错误会话发送、零越权文件访问与外传；在无法确认轮次/会话时停发；已持久化结果可审计且不得重新执行有副作用任务。
**降级**：若目标网页缺乏可靠工具请求或身份判据，保留“Hub 人工确认候选请求 + 复制/人工投递结果”的受监督模式；不得标记无人值守桥接可用。Native MCP 与 Conversation Bridge 各自单独验收。

## E03｜WorkBuddy GUI Agent（G3-GUI）
**目的**：验证非公开 API 的桌面 AI 是否能通过 GUI Driver 达到 G1/G2/G3 能力档案。
**环境**：独立测试会话、非敏感任务、空白或副本工作区；记录实际 WorkBuddy 版本、Windows 版本、显示缩放、窗口配置。
**正常用例**：找到并验证应用/会话 → 申请 Ownership → 发送明确标识的测试轮次 → 观察当前轮次 → 收集对应结果 → Core 持久化 → 释放锁。与其他窗口切换时保持身份检查。
**异常用例**：焦点失去/恢复、改变窗口大小、切换会话、用户手动编辑输入框、人工接管、工作中关闭应用、响应延迟、内容静止但任务未完成、取消请求未生效、旧结果与新结果相邻、Core/Adapter 重启。
**建议批次**：30 次正常单轮 + ≥10 次覆盖不同故障类的测试；零错会话、零旧答冒充新答、零盲目重发、零人工接管后自动恢复。
**能力判定**：G0 只观察；G1 单轮受监督发送与收集；G2 有可靠提交/终态/归属证据可加入多步；G3 有经验证断线/重启/接管后对账能力，才可申请长任务运行。不能证明 G2 则不得自动升级到 G3。
**降级**：仅连接观察，或 G1 受监督使用；保留安装和模块化能力，不降低 Core 安全标准。

## E04｜DSH ACP Adapter（G4-Protocol）
**目的**：通过协议型 Agent 证明与 GUI Driver 使用同一 Agent Turn 能力契约而无需修改 Core。
**前置**：核实被测 DSH 版本、ACP 版本、账号模型权限、启动模式、会话持久化与具体能力；不得依赖教程中未启用的高级能力。
**正常用例**：协议初始化、会话创建或绑定、发送任务、观察更新、收集对应结果；对比与 E03 相同的 LMP 输入/输出、日志和权限模型。
**异常用例**：协议版本不匹配、会话失效、取消请求、无可用模型、工具权限拒绝、断线后恢复、结果交付失败。
**必须通过**：不用为 DSH 添加 Core 应用专属分支；无法支持的会话历史/高级行为必须标记 unsupported；ACP 完成不代表业务文件结果已经验证。
**降级**：把非必需高级能力设为可选；若目标版本无稳定接口，暂只验收模拟兼容层，不宣称真实 DSH 可用。

## E05｜Terminal Executor 与 Test Runner（G5）
**目的**：验证已批准执行的真实状态记录、非批准请求拒绝及可观测副作用。
**环境**：隔离的模拟项目与不会伤害真实环境的测试用例，只有明确登记的测试 Profile。默认无无限制 Shell。
**正常用例**：查询工具版本、运行可信测试配置、记录启动/退出码/stdout/stderr/持续时间、输出截断、派生进程与可识别产物、工作区前后变化。
**异常用例**：命令名或参数不匹配、超时、测试返回非零码、执行进程未能安全终止、输入中包含试图改变 Shell 语义的内容、请求访问未授权资源、网络不可用、用户撤销执行授权。
**必须通过**：无批准不运行；未授权任意 Shell 拒绝；可辨别“成功启动”与“测试通过”；失败/超时有正确未知状态；UI 不把 cwd、Job Object 伪称为安全沙箱。
**降级**：保持 T0 API 级查询；T1 可信 Test Profile 只在用户明确审批时启用；隔离 T2 独立验收、不得声称已实现。

## E06｜持久化、恢复与重复（G6）
**目的**：验证任务历史是权威，外部动作未知不盲目重复，用户接管后不擅自恢复。
**试验点**：提交前/开始发送后/Adapter 接受后/外部执行中/结果返回但未持久化/结果已持久化但未交付/交付中/已交付但未验收，分别模拟 Core 或 Adapter 断线与重启。
**额外试验**：重复消息、旧 ACK、过期 Grant、旧 Epoch、Binding Generation 变化、人工接管完成后不按恢复确认、不同会话并发资源争用。
**必须通过**：无证据未执行才可安全重排；未知先对账；已有结果只可核验/幂等补交付；人工接管后必须明确用户同意恢复；其他无依赖任务不应无故被阻塞。

## E07｜Web Console 与模块安装（G7）
**目的**：证明普通使用者不修改数据库、不使用调试命令也可完成关键操作。
**用例**：初始化、导入本地开发者模块、查看来源与权限、添加工作区、连接网页/GUI、创建工作流、查看执行/交付/验收三轴状态、人工接管、核对、明确恢复、卸载模块时依赖告警。
**必须通过**：所有按钮显示真实操作结果；Core 未确认前不能乐观显示成功；刷新页面恢复权威快照；失败状态有明确下一步；无效模块不影响 Core 启动。

## 通用负面测试零容忍
错误目标会话写入；未授权访问/外传；用户未确认的恢复；旧 Epoch 有效写入；未知副作用自动重做；凭据原文进入普通日志。出现任何一项，相关 Gate = FAIL。
