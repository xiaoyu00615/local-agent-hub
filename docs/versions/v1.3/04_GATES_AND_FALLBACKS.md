# 04｜Gate 准入矩阵、降级策略与后续阶段

**原则：按证据逐门推进，阶段中途不得擅自扩大授权。**

## 1. Gate 定义
| Gate | 前置 | 产物与必须过关的内容 | 未通过时 |
|---|---|---|---|
| G0：F1 评审 | V1.1/V1.2 | 已批准需求与候选不变量分离；身份/Grant/状态概念无矛盾 | 返回规范评审 |
| G1：模拟协议 | G0 | E00：消息去重、ACK、Epoch、持久化、模块独立加载 | 禁止真实副作用测试 |
| G2：只读与网页桥接 | G1 | E01+E02：安全工作区读取、原会话回传、撤销与错投 | 仅保留人工监督文件分析 |
| G3：GUI Agent | G1 且验证专用会话 | E03：实际证据确定 G0–G3 等级 | 不得自行宣称无人值守 G2/G3 |
| G4：协议 Agent | G1 且服务可用 | E04：DSH 经同一契约接入 | 标记受限或替换协议样板，不改 Core 目标 |
| G5：可信工具执行 | G1/E01 | E05：受控 Profile、副作用、退出码、权限拒绝 | 仅开放 T0 查询 |
| G6：端到端恢复 | 所涉 Driver Gate 通过 | E06：故障阶段核对、接管恢复、结果交付 | 禁止对外宣称可靠自动化闭环 |
| G7：用户体验 | G2–G6 覆盖选定范围 | E07：只使用 Web 界面完成安装、授权、运行和恢复 | 修正 UI 操作契约 |

## 2. 按业务分级开放，不假装所有能力相等
- Read-only：E01+必要 Disclosure Gate 通过即可开放指定工作区的只读查询。
- Assisted Bridge：网页适配器只能保证读取或无法证明交付时，展示预览并由用户人工提交；不能声称“自动工具调用”。
- GUI G1：单轮任务人工监督，可提供受限功能；无可验证终态不得自动排队下一步。
- GUI G2：经终态与轮次关联实验证明后，允许参与多步骤自动流程。
- GUI G3：经断线、接管和恢复证据验证后，才可按授权运行更长工作流。
- T0：确定性查询 API，默认无通用 Shell。
- T1：可信、用户批准的 Test Profile，明确注明不具强沙箱保护。
- T2：独立 OS/虚拟化级隔离的专项研发，非基础平台强制依赖。

## 3. P0 安全阻断项
- 错会话自动写入或回传。
- 授权之外的文件内容访问或对外发送。
- 不确定副作用自动重试。
- 旧 Session Epoch/Generation 继续自动写入。
- 用户介入后未经明确确认恢复。
- 将测试失败、超时或仅接受 ACK 冒充业务成功。

## 4. 与 V1.1 问题的映射
- R-01 → E02；R-02 → E05；R-03 → E03；R-04/R-10/R-11 → E00/E06；R-05/R-09 → E01/E02；R-06/R-07/R-08 → E00/E04/E07。

## 5. 成果判定和开工顺序
- 若 G0 未通过：继续文档修订，不实施。
- 若 G0 已批准但 G1 未通过：允许开发测试基础设施/模拟模块，不允许将能力标为已验收。
- 若 G1 通过：按风险最小顺序实现 E01→E02；E03/E04 可并行开发但不能跨过各自 Gate。
- 若 GUI 仅 G1：首版可交付人工监督功能，完整无人值守闭环标为受限，不能冒充 G3。
- 若 T1 隔离不可实现：首版仍可保留 T0 文件查询和用户审批准许的可信测试；不能承诺强隔离。
- 若网页桥接无法证明原会话交付：首版保留 Hub 人工预览/确认投递，不宣称已实现网页自动回传。

## 6. 用户后续需要批准的开工入口
1. 明确批准 F1 架构候选冻结条款及保留例外。
2. 确定第一条实测网页与独立测试会话、模型账号授权条件。
3. 确定 WorkBuddy 独立测试会话以及是否存在许可/条款限制。
4. 确定首版 T1 可信脚本是否允许在用户审批下运行、未强隔离的告知方式。
5. 确定新项目独立根目录和测试数据目录；严禁与其他原项目混用。
6. 同意实施先从 E00 模拟测试基础设施开始，不先跑有副作用的 GUI/终端操作。

## 7. 建议的下一阶段
V1.4：围绕 E00 制作最小 LMP/Adapter SDK 契约详细设计，以及 E01/E02 的真实试验环境确认。用户尚未下达实施指令时，继续停留在文档与审查阶段。
