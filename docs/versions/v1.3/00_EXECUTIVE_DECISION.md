# 00｜V1.3 执行摘要与实施前决策

**状态：REVIEW DRAFT；不冻结未获批准的实现接口。**

## 1. 本轮唯一任务
把 V1.2 的技术可行性判断转换成能复现、能测量、能留证、能明确 PASS/FAIL/BLOCKED 的验证任务；在实施前形成 F1/F2 两级冻结清单。暂不进行产品编程、操作本机应用、修改原有工程或安装工具。

## 2. 两阶段冻结
- **F1（架构/安全契约）候选冻结**：身份和作用域、权威状态所有权、权限三轴、单会话自动写控制权、人工恢复确认、不确定副作用不盲目重放、Run 固定版本、审计与证据。
- **F2（实现协议）条件冻结**：LMP 信封字段与枚举、ACK 证明边界、重试/超时行为、模块 Driver 能力、GUI 完成判据、Web 工具桥接、终端隔离级别、UI 按钮和后台事务一致性。经模拟/真实实验核验后分项批准。

## 3. 硬性安全边界
1. Core 决定任务与权限；网页文本、模块自报、AI 回复不是授权。
2. Local Read、External Disclosure、Local Execute 独立授权，默认为拒绝。
3. 自动写操作需匹配会话 Binding Generation、Ownership Epoch、有效 Grant 与资源锁。
4. 人工接管后暂停新写入，对账成功仍**必须用户确认**恢复。
5. 已发送但是否生效不明时，保留 OUTCOME_UNKNOWN，绝不靠超时直接重投有副作用任务。
6. 已有结果补交付与重新执行任务分开，结果交付前复验会话和外传授权。
7. Job Object、cwd、命令白名单、普通同用户 Worker 不构成强文件/网络隔离。
8. 8 GB 机器作为测量基线；不强制本地运行大模型或 Windows Sandbox。

## 4. 八组验证任务
E00 模拟协议与模块；E01 Workspace Reader；E02 网页 AI 工具闭环；E03 WorkBuddy GUI；E04 DSH 协议型 Agent；E05 Terminal + Test Runner；E06 恢复与幂等；E07 Web UI 与模块安装管理。

## 5. 执行先后与依赖
文档对齐（F1 候选）→ E00 模拟 → E01 只读 → E02 网页会话工具桥接 → E03 GUI Agent、E04 DSH（可在 E00 后分支试验）→ E05 受控测试 → E06 故障恢复 → E07 无终端用户验收。每项通过前不得称完整闭环通过。

## 6. 最终决策格式
- GO：相关 Gate 全部通过，准许按批准范围进入下一工程阶段。
- CONDITIONAL GO：限制模式/能力级别，明确功能降级和不得承诺之处。
- NO-GO：任一关键安全不变量失败、缺乏身份确认或者无法评估未确认副作用。
- BLOCKED：账户、系统或应用能力前提不满足；不能用模拟结果冒充真实通过。
