# 06｜版本兼容、跨协议映射与未决问题

**状态：REVIEW DRAFT**

## 1. 四类版本不得混为一谈

| 版本 | 举例 | 变化规则 |
|---|---|---|
| LMP `protocolVersion` | 1.0 → 1.1 | major 不兼容拒绝，minor 新增可选语义经能力协商启用 |
| Module `moduleVersion` | 0.3.1 | 模块自身发布版本，独立于 LMP |
| Capability `version` / Schema | agent.turn.submit v1 | 影响输入输出或语义时检测兼容 |
| Workflow `workflowRevisionId` | revision 7 | Run 一旦启动不可偷偷替换 |

兼容原则：新增可选字段可沿 minor 演进；改变强制字段、状态机含义、权限/ACK 语义或数据安全判据必须 major 升级或使用明确适配层。未知安全相关字段、状态、权限一律拒绝，不做“忽略继续执行”。

## 2. 外部协议适配

- DSH ACP：只映射实测版本实际支持的会话与 prompt 能力。ACP 的确认语义必须转换为 LMP 对应证据级别，不能随意映射业务成功。
- ChatGPT/其他网页： Native Tool 与 Conversation Bridge 两类接入独立声明。任何网页正文都是低信任数据；交付确认由该网页 Adapter 的可验证判据决定。
- Windows GUI：UI 事件、窗口状态、正文稳定都只能提供相关证据；对人工干预的推断须标注不确定。
- MCP Tool：对外部工具的 Schema 和响应可做 Capability 映射，MCP 协议不能取代本地 Session Ownership 与 Grant。

## 3. 首版不解决的问题（非契约逃生口）

- 不保证所有网站或 Agent 都支持自动化、会话恢复和原生工具调用。
- 不保证无 API 的 GUI 程序可提供 G2/G3 无人值守证据。
- 不提供 OS 级全进程隔离；独立进程只说明故障隔离。
- 不保证端到端 exactly-once，不依赖进程/窗口 PID/HWND 的长期稳定。
- 不保证自动化能阻止人在外部应用里直接点击、输入或改变文件。
- 不在首版开放未获批准的任意 Shell 指令执行。

## 4. 待实机冻结参数（不可拍脑袋写死）

1. 具体端口、进程/IPC 驱动、Windows Launcher 技术方案。
2. 单消息体积、文件片段大小、stdout 限额、性能预算与 8GB 内存基线。
3. Worker 保活周期、通信超时、重试间隔。
4. GUI 的会话身份证据字段、完成终态特征和接管检测能力。
5. ACP SDK 支持的协议版本、会话恢复及配置能力。
6. 浏览器适配器能否自动辨别原会话和提交完成，以及合法使用条件。
7. Test Profile 是否采用真正的进程/文件隔离，以及对网络的约束。

## 6. 非兼容变更的审批机制

若未来想把 `ack.command.accepted` 解释成“目标 AI 已收到”，或想让人工接管后自动恢复，则属于**违反已确认安全语义**，必须先进行 ADR 变更、兼容影响审查与用户批准；不得通过更新 Adapter 悄悄实现。
