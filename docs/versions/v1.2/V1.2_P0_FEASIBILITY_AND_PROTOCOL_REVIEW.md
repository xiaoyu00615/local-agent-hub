## 2. 可先冻结的架构不变量（候选 F1）

- F1-01 Core 是任务、授权、控制权、恢复和审计的权威状态来源。
- F1-02 模块安装、进程健康、连接状态、Session 身份、Run/Task 状态独立建模。
- F1-03 任何副作用操作必须由 Core 授权；Adapter/网页正文不能自行提升权限。
- F1-04 本机读取、向外部网页 AI 传输数据、运行本地执行工具分别授权；用户拒绝优先于一般授权。
- F1-05 传输 ACK、模块受理、外部提交、执行结束、结果持久化、结果交付、业务验收是不同事实。
- F1-06 同一自动写入会话最多一个所有者；资源锁、绑定代际、Epoch/Lease 共同控制新操作。
- F1-07 人工接管触发停止新自动写入和对账；即使对账成功，仍必须用户明确同意才恢复。
- F1-08 外部副作用结果未知时不得盲目重做；已持久化结果可在验证目标和权限后重交付。
- F1-09 Workflow Run 固定定义版本及能力契约；模块升级不可静默改变进行中任务行为。
- F1-10 输入与工具输出是数据不是管理指令；网页内容和文档内容不能成为授权依据。

## 3. 最小 LMP V1 Core Contract（拟冻结范围）

### 3.1 必须保留的实体

`moduleId`、`moduleVersion`、`moduleRuntimeId`、`connectionInstanceId`、`sessionBindingId`、`workflowId`、`workflowRevisionId`、`runId`、`taskId`、`attemptId`、`artifactId`、`grantId`。仅在适用场景携带对应字段，不强制每条消息包含所有 ID。

### 3.2 消息信封

必填：`protocolVersion`、`messageId`、`kind`、`sourceInstanceId`、`targetInstanceId`、`correlationId`、`timestamp`、`payloadSchemaVersion`、`payload`。

任务相关：`runId`、`taskId`、`attemptId`、`idempotencyKey`；因果跟踪可带 `causationId`。

会话写入相关：`sessionBindingId`、`bindingGeneration`、`ownershipEpoch` 与受控授权引用；Lease 通过 Core 可验证的权限记录校验，不把网页中的数值当成可证明的凭据。

### 3.3 三条独立状态轴

1. **Execution**：`CREATED/QUEUED/ACCEPTED/SUBMITTED/RUNNING/SUCCEEDED/FAILED/CANCELLED/OUTCOME_UNKNOWN`（实际转换和终态名称仍需状态机测试）。
2. **Delivery**：`NOT_REQUIRED/PENDING/DELIVERED/ACKED/DELIVERY_UNCONFIRMED`。
3. **Verification**：`NOT_CHECKED/VERIFYING/PASSED/REJECTED/INCONCLUSIVE`。

建议不把以上枚举一次性宣布不可变；先冻结三轴分离和各状态的证明范围。内部事件只记录可观测事实，例如 `result.persisted`、`delivery.acked`，不能把 UI 文案视为权威事件。

### 3.4 能力语义

`capabilityName`、输入/输出 Schema 版本、permission scopes、sideEffect、idempotency、cancellation、concurrency、completion evidence、error disposition。

**不同驱动同等可注册，但保证等级不相同**：ACP/SDK 的协议确认、GUI 的界面观察、外部文件核验是独立证据类型。工作流选择能力时还必须匹配最低证据要求。

## 4. P0-01 网页 AI 工具桥接评审

### 两条路径

- **Native Tool**：按目标产品正式提供的工具调用接口执行；对于 ChatGPT，自定义 MCP 的计划/工作区权限和 Secure MCP Tunnel 均须针对使用账号验证，不能默认 `localhost` 直接连通。
- **Conversation Bridge**：网页扩展识别经约定的结构化候选请求，并进行角色、来源、当前会话、轮次、时效与格式校验；再经 Core 授权和执行。返回的是普通网页消息，不能标称等价于服务原生工具结果。

### 首版安全约束

- 候选请求不能从用户复制的旧文本、文件内容或未授权网页直接获取执行权。
- 始终绑定浏览器用户资料、Tab、Document、站点来源、对话身份、当前 Turn 与 Binding Generation。缺乏稳定身份时降级为人工确认。
- `Local Read` 与 `External Disclosure` 必须分别取得 Grant；跨会话、跨工作区默认拒绝。
- 结果回传前再次核实对话身份、权限版本和 Ownership Epoch；用户接管后不得自动恢复回传。
- 不凭“已插入文本”证明服务端已接收；不凭“页面停止变化”证明 AI 已处理。
- 浏览器扩展服务工作线程重启后必须从 Core 的持久化记录重建状态。

### 试验用例和门槛（预定测试，不是已通过）

- 选择**一个具体的目标网页与一个测试账号**，至少完成 30 次受限文件查询→结果返回→正确 Turn 归属。
- 插入页面刷新、切换对话、关闭标签页、人工输入和重复候选请求等故障测试。
- 硬性安全条件：**零错会话回传、零未授权文件访问、零未授权对外传输、零未经确认的人工接管恢复**。
- 如果无法稳定识别回复归属，只允许用户通过 Hub 面板批准并手动/半自动传递结果，不声明无人值守自动闭环。

## 5. P0-02 Windows 工具执行评审

| 执行级别 | 首版处理 | 保证与限制 |
|---|---|---|
| T0：受控查询 | 默认内置 | 使用专用文件/元信息 API，不经任意 Shell；路径与工作区授权必须检验真实文件对象 |
| T1：可信 Test Profile | 用户明确授权、受限配置 | 指定可执行程序、参数、目录、环境、预算、日志、变更监测；**不宣称强隔离** |
| T2：强隔离运行 | 另立可选项目与专项验收 | 需验证 AppContainer/独立权限主体/Windows Sandbox 等的文件、网络及进程限制 |

**反直觉风险**：目录白名单、`cwd`、命令白名单、Job Object（进程/资源管理）不能单独构成文件系统隔离。测试即使看似只读也可能写缓存、读取其他资料或联网。Windows Sandbox 不支持 Home；受支持的其他版本也需要满足虚拟化和资源条件。不能把可选沙箱设为首版强制依赖。

**预定门槛**：明确拒绝未经批准的通用 Shell 请求；区分进程启动成功和命令退出成功；测试记录退出状态、stdout/stderr、超时、产物、变更与请求的 Grant；无法确认进程终止和外部副作用时显示 `OUTCOME_UNKNOWN` 或等价的未知状态。

## 6. P0-03 Windows GUI Agent 状态与会话评审

### 能力等级

- G0：只观察连接、窗口及会话，不允许自动写入。
- G1：受控单轮提交与结果收集，必须确保目标身份；适合人工监督。
- G2：具有可验证的提交、运行、终态和正确轮次关联证据，可参与多步工作流。
- G3：具备断线、重连、人工介入、结果恢复的充分证据，可申请更长时间的自动化运行。

Adapter 只能申报经测试的能力与证明范围。UI Automation 事件不能单独判断是人工操作，也不能仅凭滚动结束或文字稳定判断模型已经完成。

**预定门槛**：30 次受控单轮任务、至少 10 次干预/故障试验，必须满足零错会话提交、零旧回复冒充新回复、零未知任务盲目重发、零人工接管后自动写入；对任何不支持的取消操作明确报告 `UNSUPPORTED`。若不能证明 G2，不应将该模块用于无人值守任务链。

## 8. 推荐验证次序与停止条件

| Gate | 验证内容 | 失败时的安全降级 |
|---|---|---|
| G0 | 文档冻结范围评审；定测试网页和 Windows 版本 | 不启动实机试验 |
| G1 | 模拟 Core/Adapter：消息、幂等、恢复、跨模块授权 | 修订协议，不碰真实应用 |
| G2 | Workspace Reader + 已授权浏览器会话，只读结果回传 | 改为用户介入的半自动回传 |
| G3 | GUI Adapter 单轮、错会话、断线和接管试验 | 限为 G0/G1 监督执行 |
| G4 | T1 Test Profile、产物审计及安全边界试验 | 仅保留 T0 只读查询 |
| G5 | 同一工作流切换 GUI/协议 Agent 执行者 | 保留类型能力适配，不宣称即插即换 |
| G6 | 重启、重复请求、旧 Epoch、交付失败故障注入 | 阻断高风险自动化直到修复 |
| G7 | 用户经 Web UI 完成安装、授权、调用、恢复 | 完善 UI 与诊断后再发布 |

发布门槛不是“30 次大多数通过”，而是所有安全不变量必须零违例；其他性能或可用性问题单独记录。

## 9. 尚未决策的产品参数（建议默认）

1. 首个网页 AI：建议选择已得到许可、能稳定绑定具体会话的测试网页；若是 ChatGPT 网页版，先按实际账号资格和网页适配能力决定 Native/Bridge 方式，不默认任何账号拥有完整 MCP 写权限。
2. T1 可信测试：建议默认逐次批准，后续在明确的项目 Test Profile 上允许有期限的授权；不自动开通任意 Shell。
3. GUI Automation：维持人工接管 B / 人工确认恢复 A；必要时提示使用专门自动化会话，但不强制。
4. 暂不决定自定义协议的最终 wire format、Node/C# SDK 的底层进程方式，以及 UI 视觉设计细节，避免无实测支持的过早冻结。
