# 08｜V1.1 之后的规范冻结与实现准备门槛

**状态：PROPOSED；非开发承诺、无时间估算**

## 阶段 1：文档一致性审查
- 核对已确认与未确认内容。
- 统一角色、术语、身份 ID、能力与事件命名。
- 绘制会话、任务、交付与工作流四组独立状态转换表。
- 明确数据读取、远程披露与执行三个独立 Grant。
- 对每项需求建立验收 ID。

## 阶段 2：P0 可行性试验设计
- 选择一个具体网页 AI，明确原生工具与会话桥接的实际差异。
- 选择一个具体 WorkBuddy GUI 样板会话，验证发送、完成和取回的证据。
- 选择最简单可信的 Test Profile，核实执行副作用边界与隔离策略。

## 阶段 3：规范冻结
- 仅当关键链路具备可操作的验收方案，才能冻结 LMP V1、会话、权限、最小 SDK 和 UI 操作契约。
- 把试验不支持的能力从 P0 降级到可选，不能用推测替代验收。
- 建立 ADR 变更程序：原因、影响、兼容、迁移、回退与批准状态。

## 阶段 4：未来开发准备（当前不启动）
- 新项目仓库与独立数据目录、规范映射、基础测试基建。
- 先模拟 Adapter，再真实文件工具，再 GUI/ACP，再测试与恢复，最后完善控制台。
- 每一阶段以可观察通过条件推进，不以“页面正常展示”代替可靠性验收。
