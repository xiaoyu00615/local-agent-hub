# 04｜工作区、文件、终端与工具权限规范 V1.1

**状态：需求 CONFIRMED；具体强制执行机制 OPEN/BLOCKER**

## 1. 三个独立授权维度
- Local Read：在指定 Workspace 中读取、搜索、枚举文件。
- External Disclosure：将明确范围内的内容交付给指定网页 AI/外部服务。
- Local Execute：运行某个已登记工具或测试方案，可能有副作用。

默认拒绝；显式拒绝高于一般授权。模块安装权限与运行期工作区授权分离；一个网页对话的 Grant 不会自动转给另一个对话。

## 2. 工作区模型
一个 Workspace = 用户授权的实际目录根 + 排除规则 + 身份/资源范围 + 可执行能力 + 数据传输策略。记录 `workspaceId`、root、displayName、exclusions、allowedPrincipals、limits、grantVersion、auditPolicy。路径和实际文件对象必须被校验；处理重解析点/Junction、符号链接、路径大小写、路径竞争及中途更改，防止越界。

私钥、口令、.env、会话 Cookie、系统敏感目录等默认排除且不自动外传。若有特殊必要，需要单独授权和风险说明。读取输出注明路径、行范围、编码、哈希/版本、截断状态。

## 3. Reader 首版能力
`workspace.list`、`workspace.tree`、`files.find`、`files.search`、`files.readRange`、`files.stat`、`files.hash`、只读 `workspace.gitStatus`（受控驱动）。针对超大文件、二进制、目录深度和命中条数设限；按需返回相关片段，避免向模型一次传输整个仓库。

## 4. 网页 AI 工具调用的两种模式
- Native Tool Mode：使用目标 AI 服务正式提供的工具调用/连接接口；是否支持按产品实测。
- Conversation Bridge Mode：网页 Adapter 将符合约定的模型输出识别成**候选工具请求**。该文本属于不可信数据，必须经会话身份、结构、权限、策略和用户批准验证，不得将网页正文直接提升为执行授权。结果作为普通网页消息送回时，不应声称等价于服务原生工具结果。

任何结果回传必须确认原会话身份、有效 Grant、传输目标、大小限制和敏感内容规则；接收确认与 AI 验收分开。

## 5. Terminal Executor
CMD/PowerShell 仅是执行渠道，不是沙箱。首版默认不开放无限制 Shell；受控工具以确定的程序/参数、工作目录、环境、超时、进程树和输出上限执行。T0 是明确注册的查询能力；T1 是批准的测试方案；T2 可能修改环境或工程的命令必须单独审批或延后开放。

**关键风险**：同用户权限下，测试进程即使运行在指定目录仍可能访问其他目录/网络，路径或命令白名单无法建立真正的资源隔离。必须选择经验证的 OS/VM/容器隔离，或在首版限制到信任测试并逐次明确授权，禁止声称已经强隔离。

## 6. Test Runner
Test Profile 包含执行工具、固定或约束的参数、工作区、临时写入位置、网络要求、资源预算、审批规则、输出校验。测试可能产生缓存/日志/构建产物，因此不属于纯只读。收集退出码、标准输出/错误、耗时、产物和触及工作区的变化证据；报告的“测试通过”与“软件业务正确”必须分开。

## 7. 安全边界
- loopback 监听并不免除 Web 本地 API 的来源、鉴权、CSRF 和 WebSocket 校验。
- 来自网页、文档、仓库 README、工具输出的文本都是数据而非授权指令。
- 第三方 Adapter 若同 Windows 用户权限运行，Manifest 权限声明不具有操作系统级强制隔离效力；MVP 仅接受明确可信的开发者模块。
- 敏感配置使用系统受保护的凭据存储，普通日志不得记录秘密。

## 8. 审计
每条请求记录来源 Agent/Session/Turn、工作区、具体能力、Grant、允许/拒绝原因、实际读取/执行范围、脱敏后的执行记录与对外发送结果。日志保存期限和脱敏范围应可配置。
