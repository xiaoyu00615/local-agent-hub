# 00｜产品需求总规范 PRD V1.1

**状态：REVIEW DRAFT**

## 1. 产品定义
Local Agent Hub 是运行在 Windows 单用户电脑上的本地模块化 AI 协作平台。通过 localhost Web Console 管理网页 AI、桌面 AI/软件、本地工作区和工具；使用统一模块能力、权限、任务和工作流协议完成受控跨应用操作。

## 2. 已确认的决策（CONFIRMED）
- C-01 首版 Windows 个人本机，浏览器访问本地控制台；不要求云端服务。
- C-02 样板为网页 AI ↔ Windows 桌面应用，并支持结果回传和核验。
- C-03 WorkBuddy 类无个人开放 API 的 GUI 应用需要作为正式适配路径；DSH 的标准协议适配为候选路径，具体能力以验证结果为准。
- C-04 Agent Adapter 使用统一能力声明，外部实现方式可不同。
- C-05 人工可以介入；检测到影响自动化的变更后，停止新的自动写入并核对。人工接管结束后即使核对通过，也必须用户明确确认方可恢复自动写入。
- C-06 模块交付策略 B：内置模块 + 本地开发者模块。新增模块不需要修改 Core 应用逻辑。
- C-07 Workspace Reader、受控 Terminal Executor、Test Runner 作为首版 P0；网页 AI 能在授权范围内提出本机只读查询且结果回到原会话。
- C-08 Obsidian 进入后续适配计划，暂不是第一条闭环的阻塞依赖。
- C-09 当前处于产品架构与协议规划，不编写产品实现代码。

## 3. 用户目标与主路径
1. 启动本地服务，打开 Web Console。
2. 添加授权工作区并配置本地读取、对外结果传输和执行权限。
3. 安装或启用模块；绑定正确的网页会话与桌面应用实例。
4. 网页 AI 发出经规范识别的查询请求；Core 审批或匹配既有授权；文件工具查询本机文件；结果被安全交付回原会话。
5. 用户审批拟执行的修改或测试；Core 调度 WorkBuddy GUI 或 DSH 等执行者。
6. Test Runner 或其他独立验证器核验产物，Web Console 给出执行、交付、验收的独立状态。
7. 故障时暂停风险操作，对账并由用户作出必要决定。

## 4. 首版必须交付
- Web Console 的模块、连接、工作区、工作流、任务、审批恢复、记录、设置等核心界面。
- 可独立加载的本地开发者 Adapter；Manifest、能力发现、生命周期检查、协议版本协商。
- 至少一类网页 AI 连接、一类 Windows GUI Agent 连接；第二种不同驱动 Adapter 用于验证可替换性。
- Workspace Reader：目录、文件名、内容搜索、分段读取、文件来源/版本记录。
- Terminal/Test：预定义安全查询能力和获批的测试方案；首版不默认开放任意 Shell。
- 持久化 Run、Task、Attempt、事件、ACK、审批、Artifact、风险状态。
- 人工接管、外部结果未知、核心重启、模块断线等的审计与恢复路径。

## 5. 非目标
云账户、多用户、远程管理、插件市场、自动运行任意 Shell、无限制读取整机文件、任意网页原生工具调用兼容性、跨产品 API 能力保证、绝对 exactly-once 外部执行、未经用户批准的无限轮自主执行。

## 6. 非功能性要求（PROPOSED）
- 8GB RAM Windows 环境可运行核心平台，性能目标待用原型测量，不声称已满足。
- Core 重启后从持久化事实恢复；禁止未知外部操作的盲目重试。
- 模块进程异常不应导致 Core 数据损坏或其他不依赖任务被无条件重跑。
- 默认只监听 loopback；Web 请求具来源和会话校验；模块和工作区使用最小权限。
- 界面操作具有明确待确认、已提交、已执行、已交付、已验收差别。

## 7. 重大可行性边界
普通网页聊天产品未必开放原生工具调用、可靠的轮次 ID 或自动消息写入。Conversation Bridge 必须以逐站适配、用户授权、有限能力为前提；未取得真实接口前不能承诺原生 tool-call 体验。Local Tool 的文件数据经网页转发到远程 AI 属于独立的数据外传操作。
